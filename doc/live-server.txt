===============================================================================
INTRODUCTION                                                *live-server.nvim*

live-server.nvim is a tiny, zero-dependency local web server for Neovim,
written in pure Lua with `vim.uv`. Start a server on any file or folder,
auto-reload the browser on file changes, and quickly reopen existing ports.

No npm. No Python. No binaries. Just Lua.

Features:
- SSE live-reload with debouncing
- CSS hot-inject (swap stylesheets without full page reload)
- Directory listing when no index file exists
- Telescope integration for path and port picking
- Same-port retargeting (reuses the browser tab)
- Auto-start on filetype
- Statusline component
- `.liveignore` support
- CORS headers
- Styled error pages (dark-mode aware)

The server binds to `127.0.0.1` unless the `host` option says otherwise
(|live-server-options|). It is meant for local dev previews, not
production; read SECURITY.md before binding beyond loopback.

===============================================================================
REQUIREMENTS                                    *live-server-requirements*

- Neovim 0.10+ (on Neovim 0.8 or 0.9 pin the plugin to v1.5.0, which
  receives no further fixes)
- Linux, macOS, or Windows

Optional:
- telescope.nvim: better path/port picker UX
- which-key.nvim: keymap group labels

COMMANDS                                        *live-server-commands*

                                                *:LiveServerStart*
:LiveServerStart        Pick a path (file or directory) and a port, then
                        start the server. If the port is already in use by
                        this plugin, the server retargets to the new path.

                                                *:LiveServerOpen*
:LiveServerOpen         Pick a port and open it in the default browser: a
                        server of this plugin at the address it is bound
                        to (a wildcard bind at its loopback address,
                        `127.0.0.1` for `0.0.0.0`), with `?t=<token>`
                        when it has one; any other port at `setup()`'s
                        `host`, a wildcard read the same way, without a
                        zone (`localhost` as written, `::1` as
                        `http://[::1]:<port>/`).

                                                *:LiveServerReload*
:LiveServerReload       Pick a port and broadcast a manual reload event to
                        all connected browser clients.

                                                *:LiveServerToggleLive*
:LiveServerToggleLive   Pick a port and toggle file watching + live-reload
                        on or off for that server.

                                                *:LiveServerStatus*
:LiveServerStatus       Show all running servers with port, root directory,
                        uptime, live-reload state, and connected client count.

                                                *:LiveServerStop*
:LiveServerStop         Pick a running port and stop that server.

                                                *:LiveServerStopAll*
:LiveServerStopAll      Stop all running servers.

CONFIGURATION                                   *live-server-config*

Configure via |live_server.setup()| or `opts` in your lazy.nvim spec. >lua

    require("live_server").setup({
      default_port     = 8000,
      open_on_start    = true,
      notify           = true,
      notify_on_reload = false,
      headers          = { ["Cache-Control"] = "no-cache" },
      cors             = false,
      index_names      = { "index.html", "index.htm" },
      auto_start       = nil,

      live_reload = {
        enabled       = true,
        inject_script = true,
        debounce      = 120,
        css_inject    = true,
      },

      directory_listing = {
        enabled     = true,
        show_hidden = false,
      },
    })
<

                                                *live-server-options*
Options:

`default_port` (number, default 8000)
    Default port suggestion in the port picker.

`host` (string, default `"127.0.0.1"`)
    Bind address, an IP address or `"localhost"`, which binds
    `127.0.0.1`; a start refuses any other string. An IPv6 address may
    carry a `%zone` of letters, digits, `.`, `_` and `-`, not checked
    against the interfaces; on macOS a zoned link-local bind starts and
    answers no request. On Windows write the zone as the interface's
    number (`"::1%1"`), since a name there such as
    `Loopback Pseudo-Interface 1` holds spaces. `inst.host` carries no
    zone, nor does any URL the plugin opens, |:LiveServerOpen| on a port
    no server of this plugin holds included. `"0.0.0.0"` serves every
    file under the root, except a dot path (unless `serve_dotfiles` is
    set) and an entry named `__live` at the root in any letter case, and
    the file you started on, at `/`, to anyone who can reach the port;
    set `token` there and read SECURITY.md first.

`token` (string|nil, default nil)
    When set, the event stream, the inject endpoint and the paths
    `protected_paths` names, but the injected client `/__live/script.js`,
    require `?t=<token>`; other files stay open, except a dot path unless
    `serve_dotfiles` is set. A start refuses a token over 4096 bytes once
    URL-encoded, since the 8 KiB cap on a request target counts the
    `?t=` query that carries it.

`protected_paths` (string[], default `{}`)
    Lua patterns of request paths that also require the token; the
    injected client, `/__live/script.js`, which holds no secret, is never
    gated. A pattern is matched against the request path and against the
    file's path under the root as the disk spells its name, so spell a
    name as the disk does: on a case-insensitive file system, a pattern
    cased otherwise gates only the spellings it matches, and a request in
    the disk's spelling is served without the token. A hard link to a
    protected file under another name is not gated. A non-empty list
    needs `token`. A pattern is read as LuaJIT's `string.find` reads it,
    so one holding none of `^$*+?.([%-` is plain text (`/draft)` gates
    every path holding `/draft)`). A `-` after an item (a character, an
    escape, a class, a set or `.`) repeats it lazily and finds no hyphen,
    so a start refuses a `-` used as a quantifier anywhere: write a
    name's hyphen as `%-`, or escape the name with `vim.pesc()`, and a
    repeat as `*`, which finds what a lazy repeat finds. A `-` that is a
    hyphen to the matcher (`%-`, inside a set, after a parenthesis or a
    quantifier) is taken. A request without the token is matched against
    every pattern on the editor's loop, so a start refuses a pattern over
    256 bytes, one holding a balanced match (`%b`) or more than two `?`
    items, and an unbounded quantifier (`*`, `+`) in a pattern that
    starts neither with `^` nor with a literal its item cannot match, or
    a second one unless the character right before its item is a literal
    that item cannot match, a capture's parenthesis aside: write
    `^/.*%.md$`, not `/.*%.md$`. A pattern `P` gates what `^.*P` gates,
    since a leading `.*` takes any prefix, so `^.*` in front keeps a
    refused pattern's matches, where a bare `^` keeps only the paths it
    matched at their first byte; a `.*` the pattern starts or ends with,
    a final `$` aside, adds nothing and, kept, makes that rewrite a
    second unbounded quantifier, so drop it (`.*%.md$` is `^.*%.md$`,
    `/secret/.*` and `/secret/.*$` are `^.*/secret/`). The paragraph
    below the README's start-key table states the rules and the cost
    they leave; a request carrying the token runs no pattern.

`asset_root` is not a setup option: a plugin that calls
`require("live_server.server").start()` passes it, and the token then
gates `/__live/asset` too.

`allowed_hosts` (string[]|true, default nil)
    More Host names a loopback bind (`127.0.0.1`, `::1`) answers. Without
    them it answers only `localhost`, a `*.localhost` name and a loopback
    address, and any other Host gets `421 Misdirected Request`, which
    keeps out a page that reaches the port through DNS rebinding. Each
    entry is a host name or an IPv6 address without brackets, with no
    port or wildcard; a start refuses any other. `true` turns the check
    off, with a warning at each start on a loopback bind. A network bind
    (`0.0.0.0`, a LAN address) has no Host check. A page under a listed
    name is the server's own origin once that name points at this
    machine, and `cors` does not govern what it reads.

`serve_dotfiles` (boolean, default false)
    Serve dot paths: while false, a request whose path, or the file it
    reaches, has a segment starting with `.` (`.env`, `.git/config`,
    `.cache/data.json`) is 404 and is left out of listings, and a change
    under one pushes no reload. `/.well-known/` at the root is served
    either way, and so is the file you started on, at `/`.

`open_on_start` (boolean, default true)
    Open the browser automatically after starting or retargeting.

`notify` (boolean, default true)
    Show the informational notices (a start, a retarget, a live-reload
    toggle, a stop). `false` silences those alone: a warning or an error,
    a start that failed among them, is always shown, and
    |:LiveServerStatus| always prints. `notify_on_reload` is its own
    switch, which `false` here leaves as it is.

`notify_on_reload` (boolean, default false)
    Show a notification on every live-reload event, whatever `notify`
    says.

`headers` (table, default `{ ["Cache-Control"] = "no-cache" }`)
    Extra HTTP response headers, added to every file, listing, asset and
    event stream served (never to an error answer); `Content-Type`,
    `Content-Length`, `Transfer-Encoding` and `Connection`, the server's
    own, are refused at start. The event stream sends its own
    `Cache-Control` in place of a caller's, and every `/__live/*` response
    drops a caller's `Access-Control-Allow-Origin`. A `Referrer-Policy` of
    `no-referrer` or `strict-origin`, in any case, is kept and sent in
    lower case, and any other is replaced by `strict-origin`.

`cors` (boolean|string|string[], default false)
    Add `Access-Control-Allow-Origin` to the root route's successful
    answers, never to `/__live/*`; a 401, 404 or 400 carries none, so a
    listed origin reads an error as a CORS failure. `true` or `"*"` allows
    all origins, a string like `"http://localhost:3000"` allows that
    origin, and a list of origins echoes a listed request Origin with
    `Vary: Origin`.

`index_names` (string[], default `{ "index.html", "index.htm" }`)
    Index file names to try when serving a directory, in order.

`auto_start` (table|false, default off)                 *live-server-auto-start*
    Automatically start a server when a matching filetype is opened.
    `false` turns it off, one an earlier |live_server.setup()| call set
    included, since each call merges into the options before it; any
    other value that is not a table is refused. The server starts once
    per directory (no duplicates). >lua
        auto_start = { filetypes = { "html" }, port = 8000 }
<
    Opening a matching file on disk in a directory no running server
    serves starts one on `port`, or, when a server already runs on that
    port, retargets it to that directory: the root follows the files you
    open, and with `host = "0.0.0.0"` it is the network-reachable root
    that moves. A new file not yet on disk starts nothing, and writing it
    does not either; |:edit| it once it is written. In a directory that
    is on disk and that no running server serves, the notice reads
    `Path not found`; in a directory not yet on disk, or one a running
    server already serves, no notice shows. A start that fails, a taken
    port among them, lets the file open and shows its notice after it.

`auto_start.filetypes` (string[])
    Filetype names to trigger on, each made of letters, digits, `_`, `.`
    and `-`; `"*"`, a `+`, an empty string or a comma is refused. A later
    `filetypes` list replaces the earlier one whole, and a later call
    that names none keeps it.

`auto_start.port` (number, optional)
    Port to use. Falls back to `default_port`.

`live_reload` (table|boolean, default the fields below)
    `false` turns the section off and `true` on, keeping its other
    fields; any other value that is not a table is refused.

`live_reload.enabled` (boolean, default true)
    Watch files under the served root and push SSE reload events. A
    change under a dot path pushes none unless `serve_dotfiles` is set,
    nor does one under an entry named `__live` at the root in any letter
    case, the file you started on excepted, and |live-server-liveignore|
    patterns match the path relative to the root.

`live_reload.inject_script` (boolean, default true)
    Inject `<script src="/__live/script.js">` into HTML a browser navigates
    to (a page, a frame, an object, an embed, a download). HTML a page's
    script fetches is served as written where the browser sends Fetch
    Metadata; a page at a plain-http LAN address sends none, and its
    fetches get the script.

`live_reload.debounce` (integer, default 120)
    Milliseconds to debounce rapid file changes before reloading, from 0
    to 2147483647; a start refuses any other value, naming
    `live.debounce`.

`live_reload.css_inject` (boolean, default true)        *live-server-css-inject*
    When a `.css` file changes, hot-swap stylesheets in the browser
    without a full page reload. DOM state is preserved.

`directory_listing` (table|boolean, default the fields below)
    `false` turns the section off and `true` on, keeping its other
    fields; any other value that is not a table is refused.

`directory_listing.enabled` (boolean, default true)
    Show a styled directory index when no index file is found.

`directory_listing.show_hidden` (boolean, default false)
    List dot entries too; it needs `serve_dotfiles`, since a listing
    names no dot entry while `serve_dotfiles` is false.

===============================================================================
LIVEIGNORE                                      *live-server-liveignore*

Create a `.liveignore` file in the served root to exclude files from the
file watcher. One pattern per line. `*` matches any characters, and a
run of `*` matches as one `*` does. Lines starting with `#` are
comments. >

    # Skip these
    node_modules
    *.log
    dist
<
A line starting with `/` is anchored at the served root: `/dist` skips
`dist/` and not `sub/dist/`. A line's text between its stars is found
in the changed path in order, with no backtracking. A rule line holding
a NUL byte matches no path and is skipped, with one warning naming the
first such line; a comment holding one stays a comment. A dot path such
as `.git/` needs no line: a change under one pushes no reload unless
`serve_dotfiles` is set.

The ignore file is re-parsed when the server retargets to a new root.

API                                             *live-server-api*

All functions are on the `live_server` module: >lua
    local ls = require("live_server")
<
Versions follow SemVer, and the promise covers what a configuration and
a plugin rely on: the |live-server-options|, the `:LiveServer*`
commands, the functions below and |live-server-server-api|; a release
that breaks any of it is a major release, while the wording of a notice,
the statusline's text and anything these do not name may change in any
release. A new option, or a value an option newly takes, comes with a
`server.features` flag (|live-server-server-api|), which a configuration
shared across installs checks before it sets it, since `setup()` refuses
an option it does not read and `setup()` or a start refuses a value it
does not take; an option is removed only in a major release. The
options added in the release that followed v1.5.0 are the exception:
`allowed_hosts` comes with `host_check` and `serve_dotfiles` with no
flag; v1.5.0 ignored an option it did not read, so a configuration may
set them there, and one that needs them to take effect checks
`server.features.start_raises`, which that release added and v1.5.0
lacks.

live_server.setup({opts})                       *live_server.setup()*
    Merge {opts} with defaults and apply configuration.
    If `auto_start` is set, registers a `FileType` autocmd. A key it
    does not read, a misspelled one among them, is refused, naming it
    (`setup does not read the key live_reload.debounc`), and the options
    stay as they were. It checks the table's own keys alone: a key a
    metatable supplies through `__index` is never refused, and the merge
    does not read it: of {opts}'s own options only `headers` is read
    through it, and inside a section only an `auto_start` table's
    fields, and those only on a `setup()` that finds no earlier
    `auto_start` table, which then keeps the table as given (a later
    call merges into the kept one and reads none of them); any other
    (`notify`, `auto_start` itself, a `live_reload` field) is left out
    without a word, so give it a plain table.

live_server.start_picker()                      *live_server.start_picker()*
    UI flow: pick a path (Telescope or vim.ui), pick a port, start.

live_server.open_existing()                     *live_server.open_existing()*
    Pick a port and open its URL in the default browser.

live_server.force_reload()                      *live_server.force_reload()*
    Pick a port and broadcast a reload event to all SSE clients.

live_server.toggle_livereload()                 *live_server.toggle_livereload()*
    Pick a port and toggle file watching on/off for that server.

live_server.status()                            *live_server.status()*
    Print running servers with port, root, uptime, live state, and
    connected client count via `vim.notify`, whatever `notify` says.

live_server.statusline()
    Returns a short string for statusline use. See |live-server-statusline|.

live_server.stop_one()                          *live_server.stop_one()*
    Pick a running port and stop that server.

live_server.stop_all()                          *live_server.stop_all()*
    Stop all running servers and clear state.

SERVER API                                      *live-server-server-api*

For plugins that run their own server. `require("live_server.server")`
and `util.random_token` and `util.secure_compare` hold the public API
that SemVer covers, as the README's "Server-level API (for plugin
authors)" section lists it: the calls and what they answer, the `start`
keys, the two instance fields, the capability flags, the HTTP routes with
their gating and refusals, and the event framing. A release that breaks
any of it is a major release. A new `start` key, or a value a key newly
takes, comes with a `server.features` flag, which a plugin checks before
it sets it, since `start` refuses a key it does not read and a value
it does not take; a key is removed only in a major release. The keys
added in the release that followed v1.5.0 are the exception:
`allowed_hosts` comes with `host_check`, and `serve_dotfiles`,
`header_timeout_ms`, `max_connections` and `sse_heartbeat_ms` with no
flag; v1.5.0 ignored a key it did not read, so a plugin may set them
there, and a plugin that needs them to take effect, or needs the dot
rule (a dot path 404 by default), checks `server.features.start_raises`,
which that release added and v1.5.0 lacks.
Everything else in these two modules is internal and may change in any
release: every other field of the instance table (read
`server.connected_client_count(inst)`, never the event-stream list
`sse_clients`) and the wording of a message, except the `EADDRINUSE`
text below. A minor release may still refuse a
request the server admits today when refusing it closes a security hole;
the requests the README lists as admitted stay admitted. A minor release
may also change how a method other than GET is answered (a `HEAD` and
the `cors` preflight's answer, which the README's request order states
as it is today, among them, and the `Allow` field), how a request line
naming `HTTP/1.2` to `HTTP/1.9` is answered, the 64 KiB cap on a
request head, and the 8 KiB cap on a request target (a longer one,
query included, is 414), which bounds the path every `protected_paths`
pattern is matched against and so the time a request without the token
costs the editor, and it may refuse at start a `protected_paths` pattern
an earlier release took, where that pattern's cost on a request path is
the reason.

Below Neovim 0.10 `live_server.server` and `live_server.util` raise on
every `require`, so a plugin that also runs on an older Neovim loads them
under `pcall`.

    server.start({cfg})          start a server and return the instance
    server.stop({inst})          close the listener, every connection,
                                 stream, timer and watcher; a second stop
                                 does nothing
    server.update_target({inst}, {root}, {index})
                                 serve another root without a restart
    server.reload({inst}, {path})
                                 broadcast a reload event; {path} is a
                                 string or nil
    server.send_event({inst}, {name}, {data})
                                 broadcast an event; {data} is a string,
                                 or nil for `{}`
    server.enable_live({inst}, {on})
                                 start or stop watching files
    server.is_live_enabled({inst})
                                 true while files are watched
    server.connected_client_count({inst})
                                 open event streams
    server.wildcard_loopback({ip})
                                 the loopback address a wildcard bind's
                                 URL shows, or nil
    util.random_token({n})       hex token of {n} bytes (2n characters),
                                 {n} from 1 to 1024, 16 when omitted
    util.secure_compare({a}, {b})
                                 whether two strings are equal

`server.start()` checks every option before it opens a socket and returns
the instance, or raises at level 0 (a message for the user, with no file
position) and leaves no socket, timer or watcher behind when it cannot
serve: an option it refuses, named in the message; a root that does not
resolve or is not a directory; a host that is not an address of this
machine (`EADDRNOTAVAIL`); a port another socket holds; a probe that
cannot check the loopback address a wildcard bind's URL names, or a
wildcard address a specific bind would shadow; a failed listen; a reload
or heartbeat timer it cannot make. Call it under `pcall`. A refusal for a
taken port carries the text `EADDRINUSE: address already in use` in each
of its three forms (the bind's own refusal, a specific bind beside a
listener on the wildcard address of its family, a wildcard bind beside a
socket on the loopback address its URL names), and a plugin may match
that text to name the port. A root whose watcher cannot start is served
with live reload off and a warning.

The instance has two public fields: `inst.port`, the port the socket
holds, and `inst.host`, the address the socket is bound to as the OS
reports it (a configured `"localhost"` reads `"127.0.0.1"`).

A call made wrongly raises at level 2, so the message names the calling
line: `reload` with a path that is neither a string nor nil,
`send_event` with a name that is not a string, a payload that is neither
a string nor nil or a name holding a line break, `enable_live` with a
flag that is not a boolean, `update_target` with a root that is not a
string, an index that is neither a string nor nil, a root or index
holding a NUL byte, an empty index (`update_target: index is empty`)
or, on a running server, a root it cannot serve, changing nothing, and
`util.random_token` with a length outside 1 to 1024.
`util.random_token` also raises when the OS offers no random source.
The instance argument is not checked: given nil, or a table `start` did
not return, a call raises, its message naming a line of the module or
of the Neovim function it calls rather than the caller's (`send_event`,
`reload` and `stop` given `{}` name a line of Neovim's own runtime), or
returns; a stopped instance is taken, and a call on it changes nothing.

A relative `default_index` is joined to the working directory at start,
and on a running server a relative `update_target` index at the call; a
path is absolute by the OS's rule, as for the `asset_root` answer, so
`C:/i.html` and `\i.html` are relative on macOS and Linux.

`update_target` returns true when the server serves the root asked, and
false with the cause when live reload is on and the new root cannot be
watched (the root moves and live reload turns off); on a stopped server
it returns false. `enable_live(inst, true)` returns true, or false with
the cause when the watcher cannot start, and live reload stays off;
`enable_live(inst, false)` returns false, as does `enable_live` on a
stopped server. `inject_script` and `css_inject` are fixed at start from
`live`: on a server started without `live`, `enable_live(inst, true)`
watches files and sends reload events, but its pages load no client
script, so no page reloads.

`util.secure_compare()` returns false at once for a non-string or a length
difference; for two strings of one length, its time does not depend on
where they differ.

`server.wildcard_loopback()` answers `"127.0.0.1"` for `"0.0.0.0"`,
`"::1"` for `"::"` and nil for any other address; a plugin calls it to
show the address a wildcard bind's URL names. Replacing it is not
supported: `start` reads it through the module table, which every plugin
in the process shares, so one plugin's replacement would move every other
plugin's probe and URL.

`server.features` holds the flags a plugin checks before it relies on a
capability: `token_auth` (the `token` option and the gated routes),
`host_binding` (the `host` option), `asset_route` (`asset_root` and
`/__live/asset`), `host_check` (a loopback bind answers only loopback
Host names and the `allowed_hosts` names, 421 otherwise), `cors_list`
(`cors` takes a list of origins; an install without it reads a list as
`"*"`) and `start_raises` (`start` raises at level 0 when it cannot
serve).

The `reload` event's data is JSON,
`{"ts":<seconds>,"path":<string>,"css":<boolean>}`, keys in that order;
Neovim 0.10 writes a slash as `\/`, so a reader decodes it and never
compares its bytes. The watcher sends no reload for a change under a
dot path while `serve_dotfiles` is off or under the `__live` entry at
the root, the file the server was started on excepted, nor for one the
root's `.liveignore` matches. On Linux, where each directory is watched
on its own, a directory named `node_modules` that is there when the
watch starts is not watched, nor anything under it, so a change there
sends no reload; one made later is watched. The README's section holds
the rest of the promise: the `start` keys, which of them are required,
what one left out means and the values each takes; how `asset_root` is
read, as a string at start and as a function on every asset request,
inside a fast event where `vim.fn` and `vim.api` raise, its answer held
to the string's rule; the order a request is checked in, from the 400
for a head the server cannot read to the 404 for a path under
`/__live/` that is no route; the routes with their token gating and
refusals, the asset route's deny list and sandbox among them; and the
event framing, with when a stream that falls behind is dropped.

A plugin that sends its own HTTP to the server sends a Host the server
can read: every bind answers 400 to a Host that is no host. An IPv6
host always goes in brackets, with a port or without one:
`Host: [::1]:8421` or `Host: [::1]`. The unbracketed `Host: ::1:8421`,
which a client builds by formatting `"%s:%d"` with `host = "::1"`,
cannot be split into host and port and is 400, and so is `Host: ::1`.

TROUBLESHOOTING                                 *live-server-troubleshooting*

Port in use ~
    The notice reads `LiveServer <port> did not start: Failed to bind
    127.0.0.1:<port>: EADDRINUSE: address already in use`, shown even
    with `notify = false`: another program holds that port. A
    `127.0.0.1` bind is refused the same way when a program holds the
    port at `0.0.0.0`, and the reverse. Pick a different port or run
    `:LiveServerStop` / `:LiveServerStopAll`.

Browser didn't open ~
    The plugin tries `vim.ui.open`; when that finds no opener it runs
    `open` (macOS), `xdg-open` (Linux) or `start` (Windows), and when that
    cannot start or fails, a notification names the URL to open by hand.

Live-reload didn't trigger ~
    - Only HTML pages get the injected script.
    - Check `.liveignore` isn't excluding the changed file.
    - A change under a dot path pushes no reload unless `serve_dotfiles`
      is set.
    - Try `:LiveServerToggleLive` off/on, or `:LiveServerReload`.

fs_event error ~
    The plugin calls the three-argument `fs_event:start()` alone, and a
    watcher that cannot start turns live reload off with a warning.
