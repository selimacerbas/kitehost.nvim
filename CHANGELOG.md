# Changelog

All notable changes to this project; versions follow SemVer, which covers what a configuration and a plugin rely on: the `setup()` options as the README's Options block documents them, the `:LiveServer*` commands, the functions the README's "API (for lua configs)" names and its plugin-author section, while the wording of a notice, the statusline's text and anything these do not name may change in any release. From `[Unreleased]` on, the format follows Keep a Changelog. The sections below it are the release notes as published on GitHub, with their headings moved one level down and the em dash written as a colon.

## [Unreleased]

### Upgrading from v1.5.0 (users)

- Neovim 0.10 or newer is required. On Neovim 0.8 or 0.9, pin v1.5.0, which keeps every hole this section's Security entries close.
- A dot path (`/.env`, `/.git/config`, `/.config/app.json`) is `404`, a listing leaves it out and a change under one pushes no reload; `serve_dotfiles = true` serves them again, and `/.well-known/` at the root is served either way.
- On a loopback bind, a request under a name other than `localhost`, a `*.localhost` name or a loopback address is `421`: a name of your own that points at this machine goes in `allowed_hosts` (`allowed_hosts = { "myapp.test" }`).
- `setup()` refuses a flag that is not `true` or `false` (`open_on_start = "no"` once opened the browser), a `live_reload` or `directory_listing` that is neither a table nor a boolean, and an `auto_start` that is neither a table nor `false`, naming the key and keeping the options it had.
- `setup()` refuses a key it does not read, naming it (`setup does not read the key tokn`), and keeps the options it had: v1.5.0 took a misspelled key without a word, so a `tokn` or a `protected_path` left the files it meant to gate open. Correct the key the message names (`token` for `tokn`).
- `auto_start.filetypes` takes filetype names alone: `"*"`, which armed every filetype, is refused, as are a `+` (Neovim refuses it in a filetype, so the entry never fired), an empty string, a comma, a brace or a line break; list the filetypes you want (`{ "html", "css" }`).
- A start refuses options v1.5.0 started with: `protected_paths` without a `token` (it gated nothing), `token = ""` (it let every request through the gate), a `host` this machine does not have (`EADDRNOTAVAIL`; it listened on every interface), an `index_names` entry holding `/` or `\` or naming `.` or `..`, `headers = false`, `token`, `protected_paths`, `index_names` or `host` given as `false`, which v1.5.0 read as unset, and a number option given as a string or a fraction (`live_reload.debounce = "200"` or `150.5`, `auto_start.port = "8080"`, a string `default_port` an auto-start uses), which `setup()` takes and every start then refuses. Set a `token` beside `protected_paths`, leave a key out rather than setting it empty or `false`, and write a number as a whole number. A `host` that is no IP address or `"localhost"` (a name, `""`, `"[::1]"`) is still refused, now naming `host`.
- A start refuses a malformed `protected_paths` pattern (`^/a[`), naming the byte: v1.5.0 started with it, served every path the matcher never read the fault on and left a request that reached it unanswered. It also refuses a pattern that would cost a request without the token much of the editor's time: over 256 bytes, holding a balanced match (`%b`) or more than two `?` items, an unbounded quantifier (`*`, `+`, `-`) in a pattern that starts neither with `^` nor with a literal its item cannot match, or a second one unless the character right before its item is a literal that item cannot match, a capture's parenthesis aside. `/.*%.md$`, which v1.5.0 took, is refused: write `^/.*%.md$`, which gates every path `/.*%.md$` gated, at any depth. In general a pattern `P` gates what `^.*P` gates, which the refusal names: `^.*` in front keeps a refused pattern's matches (`^.*private/[^/]*$` for `private/[^/]*$`), where a bare `^` keeps only the paths it matched at their first byte, so `^/secret/.*` would serve `/a/secret/x.txt`, and a `.*` at its end adds nothing (`/secret/.*` is `^.*/secret/`). A `-` between two letters or digits is refused as well: it repeats the one before it, so `^/my-notes%.md$`, which v1.5.0 took, gated `/mynotes.md` and served `/my-notes.md` without the token; write `%-` for a hyphen, or escape a name with `vim.pesc()`. A pattern holding none of `^$*+?.([%-` is plain text, as LuaJIT reads it and v1.5.0 did: `/draft)` gates every path holding `/draft)`.
- Outside Linux, a start on a port another program holds at the wildcard address (`0.0.0.0`), or a `0.0.0.0` start on one held at `127.0.0.1`, is refused with `EADDRINUSE: address already in use`, where on macOS v1.5.0 shared the port with that program; pick another port.
- `headers` are checked at start: a name must be a token and a value a string with no control byte but a tab, `Content-Type`, `Content-Length`, `Transfer-Encoding` and `Connection` are the server's own, and one field spelled two ways is refused. An `Access-Control-Allow-Origin` in `headers` no longer reaches `/__live/*`, and with `cors` set, what `cors` names replaces it; a `Referrer-Policy` other than `no-referrer` or `strict-origin` is replaced by `strict-origin`.
- A `cors` origin is written as a browser sends it (lower case, no default port, no path), or `start` refuses it.
- A request target longer than 8 KiB, its query included, is `414 URI Too Long` on every route, where v1.5.0 served it: a page asked with 10 KiB of query got `200` and gets `414` now, so a page that keeps its state in a long query string keeps it shorter. A `token` over 4096 bytes once URL-encoded is refused at start, since the `?t=` query that carries it counts toward that cap; v1.5.0 served such a token.
- A `protected_paths` pattern for a directory (`^/secret/`) now gates the directory itself: `/secret/` and `/secret`, its index file and its listing need the token, where v1.5.0 served them without it; a page that loads the directory by its own URL carries `?t=<token>` now.
- A `.liveignore` line starting with `/` is anchored at the served root, `?` and brackets match themselves, and every line is read against the path relative to the root; a line that relied on the old reading matches otherwise now. A rule line holding a NUL byte is skipped with a warning, where v1.5.0 cut it at the NUL, so `*<NUL>*` ignored every change.
- The server serves no entry named `__live` at the root, in any letter case, a file, a directory or a link to anything, nor any file in it, however a request spells that name (a hard link elsewhere in the root to a file in it is a separate name, which it serves), and a change there pushes no reload; the file you started on is the one exception, served at `/` only: move a file you kept there.
- `notify = false` silences the informational notices alone: a warning or an error, a start that failed among them, is always shown, and `:LiveServerStatus` always prints. `notify_on_reload` is its own switch, which `notify = false` leaves as it is.

### Upgrading from v1.5.0 (plugin authors)

- Call `server.start` under `pcall`: it raises when it cannot serve: an option it refuses, a root that is not a directory, a host this machine does not have (`EADDRNOTAVAIL`), a port another socket holds (`EADDRINUSE`), a failed listen; for the last three it used to return a server that was not listening where asked. `server.features.start_raises` says so, and a plugin may match the text `EADDRINUSE: address already in use` in the message to name the taken port.
- A flag given to `server.start` (`notify_on_reload`, `live.enabled`, `live.inject_script`, `live.css_inject`, `features.dirlist.enabled`, `features.dirlist.show_hidden`) must be `true` or `false`, as must the new `serve_dotfiles`; `0` or `"no"` once read as on and is now refused. `live`, `features` and `features.dirlist` must be tables and `token` a non-empty string, and `host`, `protected_paths`, `index_names`, `default_index`, `asset_root` and `headers` must be of their own types: each of these given as `false` once read as unset and now raises. `default_index = ""` is refused (`default_index must be a non-empty string`), where v1.5.0 started and answered `/` with the directory listing, its index files unread. A `protected_paths` pattern that is malformed, that the cost rules below the README's start-key table refuse or that holds a `-` between two letters or digits, is refused, naming the byte; a pattern refused for want of a `^` gates what it gated with `^.*` in front, as the refusal says. `port` must be an integer, a numeric string (`"8080"`) refused, and a non-empty `protected_paths` needs a `token`, without which it gated nothing. `host` is an IP address or `"localhost"`, a name refused before any socket opens, naming `host`. Leave the key out instead: an omitted `live` starts no watcher and injects no script, as `live = false` did, while `live = { enabled = false }` still injects the client script into every page.
- `server.start` refuses a key it does not read, naming it (`start does not read the key tokn`; a section's key dotted, `live.debounc`), where v1.5.0 ignored it and a misspelled `token` or `protected_paths` started a server that gated nothing; and it refuses a string option holding a NUL byte, naming the key (`root holds a NUL byte`). The check reads the table's own keys: a key a metatable supplies through `__index` is read when `start` reads it and is never refused, a misspelled one included, so give it a plain table; `setup()` never refuses such a key either, and its merge does not read one: only `headers` among the table's own options, and an `auto_start` table's fields, kept as given, are read through it. A refusal repeats a value with each control byte, C1 code, line or paragraph separator, bidi control or invalid byte as `?`, cut at 300 bytes (`host must be an IP address or "localhost", got "::1%?"`). A refusal of a `root`, an `asset_root` or an `update_target` root that does not resolve or names no directory gives libuv's cause, where there is one, by its error's name alone (`root <path> does not resolve (ENOENT)`, where v1.5.0 said `Invalid root: <path>`; `asset_root is not a directory: "<path>" (ENOENT)`). A bind, listen, reload-timer or heartbeat refusal carries libuv's whole text, the taken port's `EADDRINUSE: address already in use` among them, and so does the refusal of a relative `default_index`, `asset_root` or `update_target` index when the working directory is unknown (`ENOENT: no such file or directory`). The wording stays outside the promise but for that `EADDRINUSE` text, which a plugin may match.
- A loopback bind answers `421` to a `Host` that is not `localhost`, a `*.localhost` name or a loopback address, and every bind answers `400` to a `Host` that is not a host. A client that connects by another name lists it in `allowed_hosts`; `server.features.host_check` says the check is there.
- A plugin that sends its own requests brackets an IPv6 host in `Host`: `Host: [::1]:8421`. The unbracketed `Host: ::1:8421`, which formatting `"%s:%d"` with `host = "::1"` builds, is `400`, and so is `Host: ::1` with no port.
- `/__live/inject` answers `403` to a browser request its `Sec-Fetch-Site` or `Origin` marks as another site's, and an `Origin` naming another origin refuses a request that `Sec-Fetch-Site` marks as same-origin. A request that carries neither header is served with the token, and without a `token` only on a loopback bind reached under a loopback name or with no `Host` line: a network bind without a `token` refuses it, since a browser sends neither header to a plain-http LAN address, so a plugin that serves on a network bind sets `token`. gh-markdown-preview.nvim's page, opened from a LAN address on a network bind without a `token`, is refused there; a start with `token` admits it, and then gates that plugin's event stream, its images and its back channel too, each of which must carry the token. A push whose target, the encoded `data` included, is longer than 8 KiB is `414`, where v1.5.0 served it; `server.send_event` in the editor has no such bound. The cap holds on every route, so an asset request (`?p=<path>&t=<token>`) whose percent-encoded path takes it past 8 KiB is `414` too, and `start` refuses a `token` over 4096 bytes once URL-encoded.
- An `Access-Control-Allow-Origin` set in `headers` no longer reaches `/__live/*`, with or without `cors`: a page on another origin that read the event stream or the asset route through it, or through `cors`, can no longer.
- `server.update_target`, `server.enable_live`, `server.send_event` and `server.reload` raise at level 2 when called wrongly (a root or an event name that is not a string, an index, path or payload that is neither a string nor nil, an event name holding a line break, a flag that is not a boolean, a root or index holding a NUL byte, an empty index, a root a running server cannot serve), where v1.5.0 took any value but `update_target`'s root: a number was taken, and nil, a table or a boolean raised inside the library, naming its own line rather than the caller's. The instance argument is still not checked. On a running server a relative `update_target` index is joined to the working directory at the call, where v1.5.0 kept it as given and read it against the working directory of each request. `update_target` answers `true` for the root it serves and `false` with the cause when it cannot watch it, and `enable_live(inst, true)` answers `true`, or `false` with the cause; v1.5.0's `update_target` answered nothing.
- A path under `/__live/` that is none of the four routes is `404`: for a method other than GET before the method check, so a preflight there gets no origin line, and for a GET after the token gate; a method other than GET on any path whose first segment is `__live` in any letter case that is none of the four routes, or on a path whose file resolves into such an entry through a link elsewhere in the root, is `404` the same way, where any other path answers `405` or, with `cors`, the preflight. The root route answers `404` to every request whose first segment is `__live` in any letter case, whatever the entry of that name at the root is (a file, a directory, a link to anything), and to one whose file resolves into such an entry through a link elsewhere in the root, but for the file the server was started on, served at `/` only; a hard link elsewhere in the root to a file in the entry is a separate name, which it serves; the asset route serves what `asset_root` covers, such a directory included, gated by the token and never with an `Access-Control-Allow-Origin` header. The watcher sends no reload for a change there, the file the server was started on excepted, its path read as `/`.
- `asset_root` as a string must name a directory outside every credential directory (`.git`, `.ssh`, `.aws`, `.kube`, `.docker`, `.gnupg`, in any letter case) at start, which keeps the string, a relative one joined to the working directory, and its real path, so a later `:cd` is not followed. On every asset request the string is resolved again and must name that real path and a directory, or the request is a `404` and a warning, told again only after a request whose asset root resolves: a link given as `asset_root` and pointed elsewhere, or a link put at its path, is refused, and a root removed after start, which answered a silent `404`, now warns; a directory put at that same path, or a tree rebuilt above it, is served. As a function it is called on every asset request, never at start, inside a fast event where `vim.fn` and `vim.api` raise, and its answer is held to the string's rule: an absolute path by the rule of the OS (on macOS and Linux a leading `/` alone, so `C:/x` and `\x` are relative there) naming such a directory is served from, nil is a `404` with no word, and any other answer (a relative path, a path that names no directory or lies in a credential directory, a number, a table, `false`) is a `404` and a warning, as a raise is. The asset route serves a regular file alone, refuses a list of credential names and sandboxes an HTML, SVG or XML file.
- The reload event's data is JSON: decode it, never compare its bytes. A reader of the event stream joins a frame's `data:` lines with line breaks, as `EventSource` does. Every stream also carries a `: ping` comment line and a blank line every `sse_heartbeat_ms` (20 s by default), which v1.5.0 never sent: a reader that splits the stream at blank lines meets it as a block with no event and no data, and skips it.
- `host = "localhost"` binds `127.0.0.1`, and `inst.host` reads `"127.0.0.1"`. A plugin that connects to its own server connects to `inst.host`: libuv's `connect` takes an address, never a name, and raises for `"localhost"`.
- Outside Linux, a start on a port another program listens on at the wildcard address, or a wildcard start on one held at the loopback address, raises `EADDRINUSE` as a start on the same address now does everywhere; on macOS it used to share the port with that program.
- `inst.sse_clients` is internal; read `server.connected_client_count(inst)`.
- The README's plugin-author section and `:help live-server-server-api` name the server API that SemVer covers; anything of `live_server.server` and `live_server.util` they do not name may change in any release. From the release after this one, a key a minor release adds to `start` or `setup()`, or a value it newly takes, comes with a `server.features` flag to check before setting it, since this release refuses a key either does not read and a value it does not take, and a key is removed only in a major release. The keys this release adds carry no flag of their own but `allowed_hosts`, which comes with `host_check`: `serve_dotfiles`, `header_timeout_ms`, `max_connections` and `sse_heartbeat_ms` have none, and a plugin may set them on v1.5.0, which ignored a key it did not read; a plugin that needs them, or the dot rule, to take effect checks `server.features.start_raises`, which this release adds. A minor release may refuse at start a `protected_paths` pattern an earlier release took, where that pattern's cost on a request path is the reason.

### Added

- `server.start` options `allowed_hosts`, `serve_dotfiles`, `header_timeout_ms` (default 10000, 0 turns it off), `max_connections` (default 64) and `sse_heartbeat_ms` (default 20000, 0 turns it off); `setup()` takes the first two.
- `cors` accepts a list of origins and echoes a listed request `Origin`, with `Vary: Origin`; an unlisted `Origin` gets no origin line.
- `server.features.host_check`, `server.features.cors_list` and `server.features.start_raises`, for plugins that require the Host check, a `cors` list or a `start` that raises.
- `server.wildcard_loopback(ip)` answers the loopback address a wildcard bind's URL shows (`"127.0.0.1"` for `"0.0.0.0"`, `"::1"` for `"::"`), for a plugin to call; replacing it is not supported, since every plugin in the process shares the module table.
- On a token server, the injected client takes the token from the page URL, keeps it in `sessionStorage` and warns once when the server refuses it, and the opened URL carries the token, so live reload works with `token` set.
- A `: ping` comment on every event stream every `sse_heartbeat_ms`.

### Changed

- `server.start` raises when the server cannot listen: a port another program holds (`EADDRINUSE`), an address this machine does not have (`EADDRNOTAVAIL`), a failed listen, or a reload or heartbeat timer it cannot make, and it leaves no socket, timer or watcher behind. It used to return a server that was not listening while the port kept answering from the other program, or, for an address this machine lacks, one listening on every interface. Call it under `pcall`.
- `server.start` checks every option before it opens a socket and refuses, naming it:
  - a configuration that is not a table;
  - a key it does not read, a section's key dotted (`start does not read the key live.debounc`);
  - a string holding a NUL byte in `root`, `host`, `token`, `default_index`, `asset_root`, an `index_names` entry, a `protected_paths` pattern or a `headers` name or value, naming the key and leaving the value out;
  - a `root` that is not a string, does not resolve (`root <path> does not resolve (ENOENT)`, as `update_target` words it, where v1.5.0 said `Invalid root: <path>`) or is not a directory;
  - a `host` that is not an IP address or `"localhost"` (a name, `""`, a bracketed literal, `"LOCALHOST"`; an IPv6 address may carry a `%zone` of letters, digits, `.`, `_` and `-`, any other zone refused, so on Windows, where an interface name such as `Loopback Pseudo-Interface 1` holds spaces, a zone is written as the interface's number (`::1%1`), and `inst.host` reads the address without it);
  - a `port` that is not an integer from 0 to 65535, a numeric string included;
  - a `token` that is not a non-empty UTF-8 string, `token = false` included, or that is over 4096 bytes once URL-encoded (`token must be at most 4096 bytes once URL-encoded, got 8400`);
  - an `allowed_hosts` that is neither `true` nor a list of host names: a map, a list with holes, or an entry with a port, brackets, a wildcard or a spelling no `Host` carries, the entry shown with each control byte as `?`, cut at 300 bytes;
  - a `protected_paths` that is not a list of Lua patterns, a pattern whose grammar is malformed (a set not closed, a `%` at its end, a capture not closed or a `)` that closes none, `%b` without two characters, `%f` without a set, a back-reference to no closed capture, more than 32 captures), the message naming the byte and showing the pattern around it, at most 40 bytes each side, with each control byte or invalid byte as `?`; a pattern over 256 bytes, holding a balanced match (`%b`) or more than two `?` items, or holding an unbounded quantifier the cost rules refuse (an unanchored `/.*%.md$` among them), the message naming the byte and the cost, and for a missing `^` the rewrite that keeps its matches (`write ^.* in front to keep the same matches`); a pattern holding a `-` between two letters or digits, which repeats the one before it and finds no hyphen (`write %- for a hyphen`); or a non-empty list without a `token`. A pattern holding none of `^$*+?.([%-` is read as plain text, as LuaJIT reads it, and of these rules only the 256 bytes apply to it;
  - an `index_names` that is not a list of file names;
  - a `default_index` that is not a non-empty string;
  - a `live`, `features`, `features.dirlist` or `headers` that is not a table, `false` included;
  - a flag that is not `true` or `false`;
  - a `headers` name that is not a token, a value that is not a string or holds a control byte other than a tab, a field the server computes (`Content-Type`, `Content-Length`, `Transfer-Encoding`, `Connection`), or two spellings of one name;
  - a `cors` origin spelled as no browser sends it (an upper-case letter, a `%`, a path, a default port, or a port of zero, with a leading zero or over 65535), or a `"*"` entry in a list;
  - an `asset_root` that is neither a string nor a function, or a string that names no directory or one inside a credential directory, naming that directory;
  - a `live.debounce`, `header_timeout_ms` or `sse_heartbeat_ms` outside 0 to 2147483647;
  - a `max_connections` below 1.
- A refusal from `start` or `update_target` shows a value it repeats (`port`, `host`, `root`, an `index_names` entry, a `headers` name or value, a `cors` origin, `asset_root`, a key that is no name) with each control byte, C1 code, line or paragraph separator (U+2028, U+2029), bidi control or invalid byte as `?`, cut at 300 bytes. A root or an `asset_root` that does not resolve or names no directory is refused with libuv's error name alone (`(ENOENT)`); the bind, listen, reload-timer and heartbeat refusals, and those of a relative `default_index`, `asset_root` or `update_target` index when the working directory is unknown, carry libuv's whole text (`EADDRINUSE: address already in use`, `ENOENT: no such file or directory`).
- A start that fails shows `LiveServer <port> did not start: <cause>` and a retarget that fails `LiveServer <port> could not retarget: <cause>`, each naming the port asked for; the `Failed to bind port` prefix is gone.
- A `port = 0` start takes another port when the one the OS chose is held by another program on the wildcard address.
- A root that cannot be watched is served with live reload off and one warning, and `is_live_enabled` reports `false`; a watch on Linux that misses some directories under the root keeps live reload on and names the first one missed and how many.
- A server tells the user of a fault once per kind, naming its port: a listener that stopped accepting connections, a connection it could not serve or read, a reload it could not schedule or cancel, a root or directory it could not watch, a `.liveignore` it ignores or a line of it holding a NUL byte, a `protected_paths` pattern it could not read (its first 300 bytes), and an `asset_root` function that raised (the first line of its error, at most 300 bytes) or answered what it may not serve from (the answer, at most 300 bytes), and a string `asset_root` that no longer resolves to the directory kept at start, one kind for the three. Every notice the server sends starts `live-server: port <n>`, the `allowed_hosts = true` warning, a request's fault notice and the `notify_on_reload` notice among them. Four kinds are told again: a root it could not watch after a watcher starts again, a directory it could not watch at each watch start that misses one, a `.liveignore` after a move to a new root, and the `asset_root` kind after a request whose asset root resolves. A start that raises leaves no warning behind.
- `notify = false` silences the informational notices alone (a start, a retarget, a live-reload toggle, a stop); a warning or an error is always shown, and `:LiveServerStatus` always prints; `notify_on_reload` is its own switch. A start on a taken port is refused and says so under any `notify`; v1.5.0 returned a server that was not listening where asked and, under `notify = true`, reported it started.
- The start notice prints the URL the plugin opens, token included, with `0.0.0.0` shown as `127.0.0.1` and `::` as `[::1]`; the notice for a browser that did not open names the URL with the token's value left out.
- A request is read to the end of its head (64 KiB at most, then `431`). A request target longer than 8 KiB, its query included, is `414` once the head has arrived, its request line read before any header field, the Host check, the token gate or a `protected_paths` pattern; v1.5.0 served a target of any length the head held. An HTTP/1.1 request without `Host`, a request with two `Host` lines or with a `Host` that is not a host (an unbracketed IPv6 address, with a port or without one, brackets around what is no IPv6 address, a `%` not followed by two hex digits, an empty label, userinfo, a space, a port that is not digits), a request with two `Origin`, `Sec-Fetch-Site` or `Sec-Fetch-Mode` lines, a method that is not upper-case letters alone, a header name that is no token, a CR or a NUL in a header value, or a request line without an HTTP/1.x version is `400`, on every bind.
- A request target in absolute form (`GET http://127.0.0.1:8421/page.html HTTP/1.1`) is served by its path, and its authority is checked in place of `Host`; it was `404`.
- A path under `/__live/` that is none of the four routes is `404` and reads no disk, and so are `/__live` and `/__live/`: a method other than GET there, on any path whose first segment is `__live` in any letter case that is none of the four routes, or on a path whose file resolves into the entry below through a link elsewhere in the root, is answered before the method check, so a preflight gets no origin line, and a GET after the token gate. An entry directly under the root named `__live` in any letter case (`__LIVE`, `__Live`) is the server's: the root route answers `404` to every request whose first segment is such a name, whatever the entry is (a file, a directory, a link to anything), and to one whose file resolves into such an entry through a link elsewhere in the root, but for the file the server was started on, served at `/` only; a hard link elsewhere in the root to a file in the entry is a separate name, which it serves; a file kept in the entry was served at its `/__live/` path before, as any file of the root; a listing does not name the entry; an index file that resolves into it is not its directory's index, so the next index name or the listing answers; and a change there pushes no reload. The asset route serves what `asset_root` covers, gated by the token and never with an `Access-Control-Allow-Origin` header.
- A request for a file whose name holds a backslash, such as `a\b.txt` on Linux or macOS, is `400`; such a file is no longer served.
- The reload event's data is JSON written by `vim.json.encode`, `{"ts":<seconds>,"path":<string>,"css":<boolean>}`, keys in that order; Neovim 0.10 writes a slash as `\/`.
- `send_event` and `reload` raise at the caller for a name, payload or path that is not a string, and `send_event` for an event name holding a line break; a number payload was once sent as its digits.
- `update_target` raises at the caller for a root that is not a string, an index that is neither a string nor nil, a root or index holding a NUL byte, an empty index or, on a running server, a root it cannot serve, joins a relative index to the working directory at the call, answers `true` for the root it serves and `false` with the cause when it cannot watch it; `enable_live` raises for a flag that is not a boolean; `is_live_enabled` answers `true` or `false`. A retarget the server refuses is shown as a notice.
- A change under a dot path pushes no reload unless `serve_dotfiles` is set, nor does one under an entry named `__live` at the root whatever `serve_dotfiles` says, the file you started on excepted in both, its path read as `/`.
- `util.random_token` reads `vim.uv.random`, then `/dev/urandom`, and raises with neither, naming both causes; the `math.random` fallback is gone. Its length must be an integer from 1 to 1024.
- A `405` names `Allow: GET`; with `cors` set, a preflight on the root route is answered with `204`, echoing the requested headers, and one on a namespace path that is no route, or on a path whose file resolves into the `__live` entry through a link elsewhere in the root, is `404` with no origin line.
- HTML is injected with the reload script only when a browser shows it (`Sec-Fetch-Mode: navigate`: a page, a frame, an object, an embed, a download) or when the client sends no `Sec-Fetch-Mode`, so HTML a page's own script fetches gets none; with `inject_script` on, every HTML page carries `Vary: Sec-Fetch-Mode`.
- `/__live/script.js`, the injected client, is never behind the token, even when a `protected_paths` pattern matches it.
- `setup()` reads `live_reload` or `directory_listing` given as `false` as off and `true` as on, refuses a section of any other type, a flag that is not `true` or `false` (`open_on_start`, `notify` and `serve_dotfiles` among them), an `auto_start` that is neither a table nor `false`, an `auto_start.filetypes` that is not a list of filetype names and a key it does not read, naming the key, and keeps the options it had and the autocmd an earlier call armed; `open_on_start = "no"` once opened the browser. A filetype name holds letters, digits, `_`, `.` and `-` alone: `"*"` and an empty string armed every filetype, a comma two, a `+` one that never fired (Neovim refuses it in a filetype), and a brace or a line break raised after the options were replaced.
- A `.liveignore` line starting with `/` is anchored at the served root (`/dist` skips `dist/` and not `sub/dist/`); `?` and brackets match themselves, where `?` made the character before it optional and an unbalanced `[` raised inside the watcher; and a line is matched against the path relative to the root, where Linux's watcher read the absolute path, so a line naming a directory above the root dropped every reload. A line's text between its stars is found in the path in order, with no backtracking, and a run of stars matches as one star did: each star backtracked over the path, so in v1.5.0 eight stars before a letter held the editor for seconds of CPU time on a path a few dozen bytes long, the time growing with every byte. A rule line holding a NUL byte is skipped with a warning naming the first such line; v1.5.0 cut the rule at the NUL, so `*<NUL>*` ignored every change.
- `asset_root` given as a string is checked at start and must name a directory outside every credential directory (`asset_root is not a directory: "<path>"`, with libuv's error name after it when the path does not resolve: `(ENOENT)`; `asset_root is inside a credential directory (<name>): "<path>"`), and the string, a relative one joined to the working directory, and its real path are kept, so a later `:cd` is not followed; on every asset request the string is resolved again and must name that real path and a directory, or the request is a `404` and a warning, told again only after a request whose asset root resolves (a link given as `asset_root` and pointed elsewhere, a link put at its path, a root removed after start); a string naming no directory once started and answered every asset request `404`. A function is called on every asset request, never at start, and its answer is held to the string's rule: an absolute path by the rule of the OS (on macOS and Linux a leading `/` alone) naming a directory outside every credential directory, nil for none yet (a silent `404`); any other answer is a `404` and a warning naming it, where a relative answer followed the working directory, a number answered `404` without a word and a table raised inside the request, which went unanswered.
- `setup()` puts a header you give in place of its default under any spelling of the name, keeping your spelling and value.
- The picker titles read `LiveServer: Choose path` and `LiveServer: Pick file`.
- `vim.uv` replaces the deprecated `vim.loop` throughout.

### Removed

- **BREAKING:** Neovim 0.8 and 0.9 support (v1.5.0's README declared 0.8+). Below 0.10 the plugin shows one notification, "live-server.nvim requires Neovim 0.10 or newer; on Neovim 0.8 or 0.9 pin the plugin to v1.5.0", every command refuses with the same message, the statusline component shows nothing, and requiring `live_server.server` or `live_server.util` raises the message. To stay on Neovim 0.8 or 0.9, pin v1.5.0, the last release that runs there (`tag = "v1.5.0"` in a lazy.nvim spec). v1.5.0 receives no fixes and keeps every hole this section's Security entries close.

### Fixed

- When `vim.ui.open` finds no opener, the browser is opened with `open`, `xdg-open` or `start`, and a notification names the URL when that fails too; before, nothing opened and nothing said so.
- The exit hook that stops every server when Neovim quits joins the `LiveServerExit` augroup, so sourcing the plugin file again replaces it instead of adding a second.
- `host = "localhost"` binds `127.0.0.1` and the server reports that address; it raised "Invalid IP address or port".
- The opened URL brackets an IPv6 host (`host = "::1"` opens `http://[::1]:<port>/`), and an IPv4-mapped host (`::ffff:a.b.c.d`) is shown as the IPv4 address it answers on. No URL the plugin opens carries a zone: `:LiveServerOpen` on a port no server of this plugin holds opens `setup()`'s `host` without it (`fe80::1%lo0` opens `http://[fe80::1]:<port>/`), where v1.5.0 opened `http://fe80::1%lo0:<port>/`, a `%` that starts an escape in a URL.
- A request line or header split across TCP reads is served as one request; a late chunk no longer puts a second response into a streaming body.
- An aborted download, a client that half-closes and `stop` no longer leak a descriptor or raise "handle is already closing"; a client that half-closes after its request reads the whole response, where a large file arrived cut short or with no body.
- `stop` closes every connection, event stream, timer and watcher, not only the listener, and a second `stop` does nothing; a connection that sends no complete head within `header_timeout_ms` is closed.
- A raise inside the request handler answers `500` and one error notice naming the path and the cause on one line; the connection used to stay open with no answer.
- `update_target` and `enable_live` on a stopped server return at once instead of opening a watcher nothing closed, and a stopped server reports live reload off.
- A changed path holding a tab or a line break no longer yields a reload payload the page cannot parse, which turned a stylesheet swap into a full page reload.
- A save of a page and a stylesheet within one debounce window reloads the page, which a stylesheet swap left stale; a stylesheet saved by Neovim's own `:w` or by a temp-and-rename save is still swapped in place.
- A `.liveignore` that is not a regular file is ignored with a warning; a FIFO there hung the editor, as a FIFO root did, and a root must now be a directory.
- A relative `default_index`, on macOS and Linux a `C:/` or `\` spelling among them, is joined to the working directory at start, and a relative `update_target` index at the call, so a later `:cd` no longer changes the file either names.
- A directory's `index.html` that links outside the root is not served.
- A directory listing builds its links from the path, each segment encoded, never from the query, so a listing opened with `?t=` links by path alone.
- A directory listing's title and heading show the path decoded and escaped once, without the query. v1.5.0 showed the request target as sent: `/a%26b/`, the spelling of its own link to a directory named `a&b`, read `Index of /a%26b/`; a typed `/a&b/`, escaped twice, read `Index of /a&amp;b/`; and a query, a `?t=` token included, showed too.
- A `404` page names the request path without its query; v1.5.0 echoed the whole target, a `?t=` token included.
- A `401` reads `401 Unauthorized`; it read `401 OK`.
- `inst.port` is the port the socket holds, and a `port` above 65535, whose low 16 bits libuv bound, is refused.
- A later `setup()` with `auto_start = false` or an empty filetype list disarms what an earlier call armed; the old autocmd stayed and raised at the next matching filetype.
- An auto-start no longer raises out of a `:edit` run from Lua: every notice it sends waits for the edit to finish, and a refusal shows under any `notify` (the start notice, an informational one, is silenced by `notify = false`), so the file opens and the buffer's later autocmds run. On v1.5.0, with `notify = true`, a file not yet on disk or a start the bind refused raised out of such an edit, which stopped there; a taken port was reported as started and the edit completed; under `notify = false` nothing raised.
- A directory listing no longer names a link whose target is missing or lies outside the root, which it would not serve.

### Security

- A loopback bind answers `421 Misdirected Request` to a request whose `Host` is not `localhost`, a `*.localhost` name or a loopback address, before the token gate: a DNS-rebinding page could read the served files, a token baked into a page, and `.env` through the asset route. The port is never compared, so an `ssh -L` tunnel works; `allowed_hosts` adds names, and `allowed_hosts = true` turns the check off with a warning. Network binds keep the token gate. Affects v1.0.0 and later.
- A `host` this machine does not have was not refused: the server listened on every interface instead, at a port `inst.port` did not name. Such a start now raises. Affects v1.3.0 and later.
- A NUL byte or a backslash in a request path is `400` before the token gate, and `protected_paths` is checked again against the file's name on disk, so `/content.md%00`, `/CONTENT.MD` on a case-folding volume, and a link to a protected file no longer skip the token. Affects v1.4.0 and later.
- A `protected_paths` pattern for a directory (`^/secret/`) gated the files under it but not every request for the directory itself: `/secret` served the directory's index file and, with none, its listing, which names the protected files, without the token, and on v1.5.0 `/secret/` did too. The directory, its index and its listing now need the token under either spelling. Affects v1.4.0 and later.
- On a server with a token, a request was matched against the `protected_paths` patterns on the editor's loop until one matched, a request carrying the token included, with no bound on the path or the pattern: on v1.5.0, `/.*%.md$` took seconds of CPU time for one request on a path a few dozen KiB long. A request target over 8 KiB is now `414`, `start` refuses the costliest pattern shapes, and a request carrying the token runs no pattern; SECURITY.md states the cost left, which is a limit, not a bound. Affects v1.4.0 and later.
- Dot segments (`/.env`, `/.git/config`) are `404` unless `serve_dotfiles = true`, the file you started on excepted, served at `/` only; `/.well-known/` at the root stays served, and a listing shows dot entries only with both `serve_dotfiles` and `show_hidden`. The asset route refuses credential files by name (`.env`, `.env.*`, `.npmrc`, `.netrc`, `id_rsa` and the like), key and certificate files by extension (`*.pem`, `*.crt`, `*.key` and the like) and paths through credential directories (`.git`, `.ssh`, `.aws` and the like) at any depth; it serves a regular file alone, images in other dot directories stay served, and no deny list is complete. Affects v1.0.0 and later; the asset route's part, v1.5.0 and later.
- `/__live/inject` refuses, with `403`, a browser request from another site or another port (`Sec-Fetch-Site` other than `same-origin` or `none`, or a foreign `Origin`, which refuses and never admits); a request with neither header, such as curl's, is served as before on a loopback bind reached under a loopback name or with no `Host` line, which no browser sends, and refused on a network bind without a `token`, where a browser sends neither header to a plain-http LAN address. Affects v1.2.0 and later with no `token` set.
- Outside Linux, a bind to a specific address (`127.0.0.1`, `::1` or a LAN address) refuses a port another program listens on at its family's wildcard address, and a wildcard bind refuses one another socket holds at the loopback address its URL names. On a wildcard bind the other program took the page's requests, token included; a specific bind beside a wildcard listener served live-server's own page and took the loopback requests meant for the other program. The check runs once, at start: a program that binds the loopback address after the start still takes the requests sent to the URL, token included. Affects v1.0.0 and later; a wildcard, `::1` or LAN address bind, v1.3.0 and later.
- `server.start` refuses `token = ""` and a token that is not a string: an empty token passed every gate. Affects v1.4.0 and later.
- `cors` never adds `Access-Control-Allow-Origin` to `/__live/*`, nor does one in `headers`, and with `cors` set an `Access-Control-Allow-Origin` given in `headers` is replaced by what `cors` names, so under a list an unlisted `Origin` gets none. Every response carries `Referrer-Policy: strict-origin` (a caller's `no-referrer` or `strict-origin` kept, any other value replaced), so no Referer carries the page's path or query, the token included, not even to the server's own origin; a page's own `<meta name="referrer">` can still change it. A 404 names the request path, never a filesystem path, and HTML, SVG and XML from the asset route carry a `sandbox` directive in `Content-Security-Policy` (after any policy set in `headers`). Affects v1.0.0 and later; the asset route's part, v1.5.0 and later.
- A `Content-Type` passed in `headers` once replaced a served file's type, past the asset route's sandbox, and a framing field passed there went out beside the server's own; both are now refused at start. Affects v1.0.0 and later.
- A line break inside an event's payload, through `/__live/inject`'s data or a path, ended the frame early and started a forged event, and an event name holding a line break injected a `retry` field; every payload line is now its own `data:` line and `send_event` refuses such a name. Affects v1.0.0 and later through a path, v1.1.0 through `send_event`, v1.2.0 through `/__live/inject`.
- A client that reached the port could open connections without limit, each one a descriptor of the editor's own process; the server now closes a connection accepted while `max_connections` (64 by default) are open. Affects v1.0.0 and later.
- An idle event stream was never written to, so a proxy's idle timeout cut a live page's stream and a peer that vanished without closing its connection stayed listed, holding a connection place; the server now writes a comment line to every stream each `sse_heartbeat_ms` (20 s by default). Affects v1.0.0 and later.
- A client that stopped reading an event stream without closing it made the editor queue every later event for it without limit; a stream more than 1 MiB behind for longer than a second, or more than 8 MiB behind at all, is now dropped, and a reader that keeps up is not dropped for one large event or a burst while it stays within 8 MiB. The second counts time the editor spends blocked, so a send right after a longer block can drop a reader that keeps up. Affects v1.0.0 and later.
- The error of a failed write to an event stream went unread and a raise inside one went unreported; a failed write, a heartbeat's included, now drops the stream and closes its socket, and a raise is reported once. A response or stream whose first write fails closes its connection there, and such a stream is never kept. Affects v1.0.0 and later.
- A `.liveignore` over 64 KiB, or one that cannot be opened, is ignored with a warning; a link to a large file hung every start. Affects v1.0.0 and later.
- A notice shows a control byte, a C1 code or a bidi control from a request path or a file name as `?`, so a peer's bytes cannot act on the terminal or reorder the line; so do the notices the commands send that name a root or repeat the server's refusal (a start, a retarget, `:LiveServerStatus`, a start that failed). Affects v1.0.0 and later.

## [1.5.0] - 2026-07-07

### Features
- **Configurable bind address**: new `host` setup option (default `127.0.0.1`); set `"0.0.0.0"` for network access. Thanks @icyveins7 (#5).
- **Token auth in setup**: `token` and `protected_paths` are now exposed as setup options, so network binding can actually be secured from the plugin config.
- **Asset route**: new token-gated `/__live/asset?p=<relpath>` endpoint serves files relative to a configurable `asset_root` (a directory or a function), with realpath containment. Powers relative-image support in markdown-preview.nvim.
- **Capability flags**: `require('live_server.server').features` lets sibling plugins feature-detect against an independently-versioned install.

### Security
- **Path-normalization auth bypass fixed**: the token gate matched the raw request path while files were served after URL-decoding and slash-collapsing, so `//content.md`, `/content%2emd`, and `/x/../content.md` could evade the token on a network bind. The path is now canonicalized once and used for both the auth check and the file mapper.
- **SSE CORS**: the reload stream no longer sends a hardcoded `Access-Control-Allow-Origin: *`; it emits CORS only when configured.

### Docs & tests
- README documents the network-exposure trade-offs and the `ssh -L` alternative.
- New test suites for host binding and the asset route; token-auth tests extended with path-normalization cases (44 tests total).

## [1.4.0] - 2026-05-24

- **Feature:** Optional token auth for protected endpoints. When `cfg.token` is set, the SSE stream (`/__live/events`), the event injection endpoint (`/__live/inject`), and any path matching `cfg.protected_paths` (list of Lua patterns) require `?t=<token>` on the request. Static assets stay reachable so the browser can bootstrap. (#4)
- **API:** New helpers `util.random_token(byte_len)` (hex token from `/dev/urandom`, with a `math.random` fallback) and `util.secure_compare(a, b)` for constant-time-ish validation.
- **Backward compatible:** `cfg.token = nil` (the default) keeps the previous behaviour. No existing caller is affected.

## [1.0.0] - 2026-02-12

### live-server.nvim v1.0.0

Pure-Lua local web server for Neovim with live-reload. Zero external dependencies.

#### Features

- **SSE live-reload** with configurable debouncing
- **CSS hot-inject**: swap stylesheets without full page reload
- **Auto-start** on filetype (e.g. open an HTML file → server starts)
- **Statusline component**: `[LS :8000]` for lualine/statusline
- **`.liveignore`**: skip file watcher noise (`node_modules`, `*.log`, etc.)
- **CORS headers**: configurable `Access-Control-Allow-Origin`
- **Telescope integration**: path and port pickers
- **Directory listing**: styled index when no `index.html` exists
- **Styled error pages**: dark-mode-aware 404/400 pages
- **Same-port retargeting**: reuse browser tab when switching roots
- **Custom index names**: try `index.html`, `index.htm`, or your own list
- **Vimdoc**: full `:help live-server.nvim` documentation
- **Graceful exit**: servers stop automatically on `VimLeavePre`

#### Install

```lua
{ "selimacerbas/live-server.nvim", opts = {} }
```

See [README](https://github.com/selimacerbas/live-server.nvim#readme) for full setup and configuration.
